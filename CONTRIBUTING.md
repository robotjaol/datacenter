# Contributing

Start with a reproducible issue: the requirement or model boundary, input scenario, expected behavior, observed evidence and proposed acceptance check. Keep physical assumptions distinct from sourced measurements.

For code changes, run the unit tests, CLI and repository verifier. Add tests for a changed physical/financial invariant or failure mode rather than mirroring implementation. Update methodology, schemas and assumption provenance together. Rebuild reference outputs only when the intended baseline changes, and explain metric deltas in the pull request.

For sourced contributions, record title, publisher, publication/version, URL, access date, license, scope and limits. Do not upload vendor CAD, licensed standards, confidential site information, account data or unlicensed benchmark datasets. Original concept material is MIT; third-party contributions retain applicable notices.

Review criteria: correct units and boundaries; justified model fidelity; reproducibility; adverse-case handling; clear evidence; usable documentation; no inflated compliance claims. Follow respectful, constructive discussion focused on the work. Disclose assumptions and unresolved disagreements.
